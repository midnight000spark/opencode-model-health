# opencode-model-health

TUI-плагин для OpenCode V2: по команде проверяет, какие модели провайдера реально
отвечают, и показывает «что поднято, что упало» в одном диалоге.

Список моделей берётся у самого провайдера (`GET /models`) и фильтруется до
chat-моделей; если эндпоинт недоступен или вернул пустой список — фолбэк на
список из конфига OpenCode, с коротким тостом-предупреждением. Сама проверка — это
маленький `chat/completions`-запрос к каждой модели: в отличие от `GET /models`, он
доказывает, что ключ принят **именно для этой модели**. Ключ нигде не логируется и
не показывается.

## Что показывает

Команда срабатывает единично: пока идёт проверка, повторный вызов показывает тост
«уже выполняется…», а не открывает второе окно.

Окно прогресса открывается **сразу** (до сетевого обмена) и обновляется в живом
режиме: фаза синхронизации, затем полоса `[████░░░░] 12/156 8%` и лог последних
результатов (`✅ gpt-5.5 · работает · 210ms`). Строки появляются по мере
готовности каждой модели; показываются последние 12. По завершении окно прогресса
закрывается и открывается список результатов.

Диалог результатов отсортирован «проблемы сверху», есть поиск по id/имени и
строка статуса вида `145/156 ✅ · 5 проблем · только что`.

| Иконка | Метка | Смысл |
| --- | --- | --- |
| ✅ | работает | HTTP 2xx |
| 🟢 | отвечает (мал. лимит probe) | модель ответила, но отклонила сам размер пробника (напр. reasoning-модель и `max_tokens`) — доступа это не отменяет |
| ⛔ | нет доступа | 401 / 402 / 403 / прочий 400 |
| ⏳ | квота/лимит | 429 |
| ❓ | нет модели | 404 / 410 |
| ⚠️ | апстрим недоступен | 5xx |
| 🌐 | сеть/таймаут | транспортная ошибка или abort |

`🟢 reachable` считается здоровым: он не попадает в счётчик «проблем», но виден
в списке отдельной меткой.

## Откуда берётся список моделей

Плагин спрашивает провайдера — `GET {baseURL}/models` — и сам решает, что из
ответа является чат-моделью. Так видны и новые модели, которых ещё нет в конфиге
OpenCode.

Фильтр «пригодно для чата»:

- у модели есть OpenAI-совместимый эндпоинт (`openai`, `chat`, `completions`,
  `responses`) и нет `image-generation`;
- имя не совпадает с медиа-семействами (`embed`, `rerank`, `tts`, `asr`, `speech`,
  `whisper`, `audio`, `image`, `imagine`, `flux`, `gptimage`, `dall`, `video`,
  `sora`, `kling`, `veo`, `moderation`, `ocr`, `realtime`, `voice`, …);
- имя не является служебным/тестовым (`mock`, `deepai`, `agent-tools`, `all`,
  `turbo`).

Для моделей, которые есть и в провайдера, и в конфиге, сохраняется человекочитаемое
имя и возможности из конфига; новые берутся как есть (`name = id`).

Если `GET /models` не отвечает (сеть, 4xx/5xx, битый JSON) **или возвращает
пустой список** — берётся список из конфига OpenCode, а в TUI показывается
короткий тост-предупреждение. Пустой ответ считается сбоем discovery, а не
достоверным «моделей нет».

Списки фрагментов живут в `src/discover.ts` (`NON_CHAT_NAMES`, `INTERNAL_NAMES`,
`INTERNAL_IDS`) — это основное место для расширения эвристики.

## Установка

Требуется OpenCode V2 (плагин собран под `@opencode/plugin@2.2.5`) и Bun.

```sh
git clone https://github.com/midnight000spark/opencode-model-health.git
cd opencode-model-health
bun install
```

Проверка без TUI (тот же код, что в плагине, но headless):

```sh
# reformboss — пример провайдера; укажи id своего из opencode.json
bun run src/cli.ts --provider reformboss --mode text --concurrency 4
bun run src/cli.ts --provider reformboss --mode all --json      # машиночитаемо
```

## Подключение к TUI

OpenCode сам подхватывает плагины из каталога `<config>/plugins/<name>/`, где
`<name>` — папка с точкой входа `tui.ts`, экспортирующей `default` (определение
плагина). Проект подключён симлинком:

```sh
# запускать из корня репозитория
ln -sfn "$PWD" ~/.config/opencode/plugins/model-health
```

В корне проекта лежит `tui.ts` — shim, который реэкспортит `./src/tui.ts`,
поэтому OpenCode находит точку входа. Больше ничего настраивать не нужно:
`cli.json` править не требуется.

Проверить, что плагин виден:

```sh
opencode plugin list      # в списке появится путь …/plugins/model-health
```

Активация: `/reload` в TUI (или обычный перезапуск).

### Опции

При автоподхвате опции не передаются — используются значения по умолчанию
(см. таблицу ниже). Передать свои опции можно только через `cli.json` объектом
с именем пакета, а не путём к файлу:

```jsonc
{ "plugins": [{ "package": "opencode-model-health", "options": { "mode": "all" } }] }
```

Пакет не публикуется в npm (`"private": true`) и подключается из исходников
симлинком (см. выше), поэтому на практике опции из `cli.json` не применяются —
работают значения по умолчанию. Чтобы сменить провайдера, поправь константу
`DEFAULT_PROVIDER` в `src/check.ts` (или передай `--provider` в headless-CLI).
Таблица ниже описывает контракт опций: он включится, если поставить плагин как
обычный пакет.

### Почему не «путь в cli.json»

Записи `cli.json` вида `"plugins": ["/abs/file.ts"]` или `"file:///abs/file.ts"`
для файла **вне** каталога конфига OpenCode не загружает: он импортирует только
плагины из `<config>/plugins/` и npm-пакеты. Поэтому используется симлинк выше.

## Использование

- Палитра команд: `Models: health check`
- Слэш-команда: `/models-health`
- Клавиши: `<leader>mh` (лидер — как задан в `cli.json`)

В диалоге:

- `Enter` / клик — экран с деталями модели (id, статус, HTTP, причина, задержка), затем возврат к списку;
- `Ctrl+o` — перепроверить (принудительно пересканировать, минуя кэш);
- `Ctrl+y` — переключить «только текст» ↔ «все» (VL/omni);
- `Esc` — закрыть.

## Опции (только через `cli.json` объектом с именем пакета)

| Опция | По умолчанию | Описание |
| --- | --- | --- |
| `provider` | `reformboss` (пример) | id провайдера в `opencode.json`; **поменяй на свой** |
| `mode` | `text` | `text` — только чисто текстовые; `all` — плюс VL/omni |
| `ttlMs` | `600000` (10 мин) | сколько живёт кэш последнего скана |
| `concurrency` | `4` | одновременных запросов |
| `timeoutMs` | `30000` | таймаут одного запроса |

## Откуда берётся ключ

`baseURL` и `apiKey` плагин берёт из data-фида TUI
(`context.data.location.provider`), с запасным вариантом
`context.client.provider.get({ providerID })`. В коде ключ используется только в
заголовке `Authorization`. В вывод попадает лишь человекочитаемая причина ошибки,
и та проходит через маскирование: схемы `Bearer`/`Basic`/`Digest`/`Token`, ключи
`sk-…`, URL-креды `user:pass@` и присваивания `api_key=…` заменяются на `***`
перед показом, выводом в `--json` и записью в кэш.

## Ограничение

Переключить текущую модель сессии из плагина нельзя: API `context.ui.model`
даёт только `current()` и `variant.set()`. Диалог подсказывает, какая модель
здорова, а модель выбирается штатным пикером (`<leader>m`).

## Разработка

```sh
bun run typecheck                  # tsc --noEmit
bun test                           # юнит-тесты + оркестрация
bun run health -- --provider reformboss --mode text   # headless-проверка
```

Структура: `classify` (HTTP → статус), `probe` (запрос + worker-pool), `redact`
(маскирование секретов), `discover` (список моделей у провайдера + фильтр),
`select` (какие модели проверять), `cache` (TTL/сводка), `format` (иконки/метки),
`dialog` (цикл диалога + экран деталей), `progress` (контроллер прогресса +
палитра), `progress-view` (JSX-вид прогресса), `check` (оркестрация без хоста),
`tui` (склейка с OpenCode), `cli` (headless). Общие утилиты — `http`, `json`.

Живой диалог прогресса — Solid-компонент, поэтому в devDependencies есть
`solid-js` и `@opentui/solid` (только для типов: рантайм даёт сам OpenCode).
Файлы с JSX обязаны иметь расширение `.tsx`; загрузчик OpenCode транспилирует
их через `@opentui/solid`.
